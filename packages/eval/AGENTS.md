## 缓存复用

缓存复用是一个非常复杂的需求，评测过程中可能有非常多预期或非预期的因素会影响到评测的结果。

以最极端的情况来说，即使我们把评测过程所有的配置数据全都 hash 了个遍，但我仍然可能通过注入环境变量或者其他什么外部方式来影响到结果。从这种角度而言，想要尽可能覆盖 hash 到的因素是不可能完成的任务。

综合而言，缓存复用存在 integrity - 复用效率 - 设计复杂度的不可能三角。

对于评测来说，integrity 是一个非常重要的考量，其重要性理应大于所有其他因素。
为此本框架选择在该三角中取 integrity - 设计复杂度这两个维度，采用非常保守的缓存复用策略：直接按照评测代码所在的 commit hash 进行缓存。

用户只需要保证评测代码是完全 versioning 的，也即，所有将会影响到评测结果的因素全部体现在代码里而且能够被 git 所追踪。
只要用户能够提供这一点，那框架就能够利用 git 实现高 integrity。
